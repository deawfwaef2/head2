# 画质提升 · 头发：发片 → 真发丝（Card-to-Strand）方法说明

> **v2（Stage 49-C）更新摘要**：两级成缕 + 12% 散发 + 飞发 + 绒毛碎发；体积 AO 改为密度体素射线累积；细线覆盖率抗锯齿（alpha-to-coverage）；原发片不再作为可见底衬（只留贴头皮 1cm 的暗色遮挡层 + 全部作阴影代理）；高光按每根发丝抖动倾角并沿发长起伏，碎成闪丝。默认「标准」约 4.8 万根。详见第 7 节。

> 写给之后接手的 agent / 开发者。代码：`画质提升/src/strandHair.js`（约 470 行，无外部依赖，只用 three r170）。
> 接入点：`画质提升/src/demo.js` 里的 `buildStrands()`。**主项目没有接入**。演示面板里的「头发渲染」可以在「真发丝」和「原版发片」之间切换，方便对比。

## 1. 一句话区别

| | 主项目（`src/three/*`） | 本模块（`画质提升/src/strandHair.js`） |
|---|---|---|
| 头发的几何 | 艺术家**发片**（带 alpha 贴图的面片，每个发型约 9–17k 三角形） | 以发片为**形状容器**，在上面长出 **1.2 万–10 万根 3D 发丝**（细带） |
| 发丝走向 / 切线 | 在片元着色器里用 UV 屏幕空间导数**猜**（`hairKajiyaKay.js`、`updateArtistHairFlow`） | 预先在 3D 曲面上**追踪**出真实发丝曲线，切线是曲线本身的切线 |
| 高光模型 | Kajiya-Kay 双瓣（经验模型） | **Marschner R / TT / TRT** 三瓣（Karis 2016 实时近似）+ Kajiya 漫反射 |
| 发量感 | 靠贴图里的明暗，加上发片层叠 | 体积 AO（发量内部变暗）、成缕（clumping）、每根颜色和高光不同 |
| 发梢 / 轮廓 | alpha 测试或混合，近看是“锯齿纸片” | 每根发丝的末端自然变细、长短不齐，有少量飞发 |
| 阴影 | 发片自身投影 | 原发片缩进 1.2 mm 作内层底衬，并兼作 **VSM 阴影代理**（发丝本身不投影） |
| 主项目注释立场 | “no procedural strands or extra shells” | **形状 100% 来自原资产**，只是采样和重建，不改造型；还能一键切回 |

结论：主项目已经把“发片上的着色”做到了上限。真正的瓶颈是**几何**：发片就是“纸片”，近看必穿帮。所以本模块不再继续调发片着色，而是在发片上**重建发丝几何**。

## 2. 流程（对应代码里的函数）

1. **`morphedHeadSoup(skinMesh)`**
   取 CPU 端已应用 morph 的头皮三角形（`asian_youth` 等），放进 `TriGrid`（1 cm 网格）。后面两处要用：判断发根端，以及把发丝推到头皮外面。
2. **`alphaSamplerFromTexture(tex)`**
   把发片贴图画到 canvas 上，在 CPU 端采样 alpha。**注意 glTF 贴图 `flipY=false`**，代码按 `tex.flipY` 处理。
3. **`generateStrands()` → 引导发**
   - **撒种子**：概率按「三角形面积 × 该处 alpha」，再用 3.5 mm 的占用网格做间距控制（每格最多被 2 根引导发经过），让引导发均匀分布。
   - **追踪**：从种子出发，沿该三角形的 **dP/dv** 双向前进（用重心坐标解出 UV→3D 的雅可比矩阵），步长 2.2 mm。每一步都吸附回最近的发片表面（TriGrid 最近点）。遇到以下情况就停：
     - 发片 alpha < 0.1（到发梢了）；
     - 离开发片超过 3.8 mm，或方向急转 > 70°（到了发片边缘）。
   - **决定发根**：两端中**离头皮更近**的一端是发根。不能看 UV 朝向，见第 4 节坑 2。
   - **重采样**：按弧长重采样成 6–30 个点，做 2 次平滑，再用头皮 SDF 推到头皮外 1.3 mm。
4. **子发（`buildChildren`）**
   - 每根引导发生成 10–25 根子发。偏移量分布在一个椭圆里：宽 6.2 mm，厚 3.4 mm（发片宽、发层薄）。
   - 偏移在**平行移动标架**里进行（不用 Frenet 标架，否则曲率为 0 处会翻转）。
   - 成缕：从发根到发梢，向引导发收拢 35%→85%。
   - frizz 0.28 mm 的细卷；1.5% 的飞发；发梢长度 `tEnd ∈ [0.8, 1]`。
5. **体积 AO**
   把发丝点按方位角 × 仰角分箱，求每箱的外轮廓半径，用「点到外轮廓的深度」近似发量内部的遮蔽。
6. **几何格式**
   每个点 2 个顶点（`aSide = ±1`），属性有：
   - `aTan`（切线）
   - `aT`（0 = 发根，1 = 发梢）
   - `aRand`（每根的随机数）
   - `aAO`
   - `normal`（体积法线 = 离开头部中心的方向）
7. **`createStrandMaterial()`**：在 `MeshStandardMaterial` 上打 `onBeforeCompile` 补丁。
   - **顶点着色器**：在视图空间里沿 `cross(T, V)` 方向展开成面向相机的细带。宽度取 `max(世界宽度 0.08 mm, 0.62 像素)`，发梢变细，发根也稍微变细，让发际线柔和。`uPxScale = 2·tan(fov/2)/画布高度`，**每帧更新**。
   - **片元着色器**：
     - 用自己的 Marschner 版本替换 `RE_Direct_Physical`；
     - 法线覆盖为体积法线（在 `normal_fragment_begin` 之后）；
     - 每根发丝的颜色、高光强度、高光偏移角都按 `aRand` 抖动，避免“一整片塑料光”；
     - AO 乘进 `diffuseColor`。
8. **原发片作内层底衬**
   发丝模式下，原发片：
   - 用 `uInset` 沿头部径向内收 1.2 mm；
   - 压暗到 55%；
   - `alphaTest` 提高到 0.62；
   - 隐藏原来的 tips pass。

   它的作用是遮住头皮缝隙、提供发量深色底，同时继续 `castShadow` 作阴影代理。

## 3. 性能

- 时间（headless SwiftShader，比真机慢）：v1 的 1500–1700 根引导发追踪约 2–4 s，子发 0.3–0.7 s；v2 的数据见第 7 节第 18 条。
  - 真机大约是这个的 1/3–1/2。结果按「发型 × 密度」缓存。
- 顶点数（每根约 30 点 × 2 个顶点）：
  - 「标准」约 2–3 万根 ≈ 0.9–1.3 M 顶点；
  - 「高精」约 3.3 万根 ≈ 2 M；
  - 「极致」约 10 万根，需要独显。
- 引导发数量受 3.5 mm 占用网格（`occCell`，每格 ≤ 2）和尝试次数（`guides × 6`）限制。实测一个发型约 1400–1750 根就饱和了，**到上限后再加 `guides` 也不会增加引导发**，所以「高精/极致」主要是增加子发。想要更多引导发，就把 `occCell` 调小。
- 发丝**不投影**，阴影由发片代理负责，这能省掉一整个 shadow pass。

## 4. 坑与注意事项（都是实际踩过的）

1. **子发索引的基址**：`base` 必须是**顶点**计数 `vp`，不能用 `vp/2`。用错时画面“大体正常”，但实际只画出一半发丝，还会出现横穿额头的长直线（三角形把不同发丝的顶点连在了一起）。**看到细长直线乱飞，先查索引。**
2. **UV 的 V 方向不等于“朝发梢”**：直发类资产约 97% 的 +V 朝下（`hair_long01` 的 mean dP/dv.y = −0.78），但盘发和马尾（`ballerina_bun` +0.55，`ponytail01` +0.23）方向混乱。**发根要用离头皮的距离来判断。**
3. **glTF 贴图 flipY=false**：CPU 采样 alpha 时，如果按 three 的默认 flipY 来翻，会把发梢当成发根，结果追踪立刻终止。
4. **最小像素宽度必须每帧更新**：`uPxScale` 依赖画布高度和 fov，窗口缩放或换镜头后不更新，发丝会忽粗忽细，或者闪烁、消失。宽度过细（< 0.5 px）在 MSAA 下会断成虚线；过粗（> 1 px）会像“毛线”。
5. **不要给发丝开 castShadow**：几万根细带进 VSM 会出现大块的脏阴影，还要多渲染一遍几何。让原发片当代理。另外，three r170 的 VSM 也会把 receiveShadow 物体画进阴影图，由于宽度为 0 所以无害，但别被吓到。
6. **Marschner 的 R 瓣是白色的**：这是物理正确的，但如果 β 太宽，或者每根高光强度都一样，深色头发会发灰发白（之前发片 KK 也踩过）。解决办法：
   - βR ≈ 0.13；
   - 每根抖动 ±20% 宽度、±0.045 rad 偏移、0.55–1.45 倍强度；
   - `envMapIntensity` 降到 0.18（环境光的 GGX 镜面在体积法线上会形成一层灰雾）。
7. **TT（逆光透射）用 `pow(baseColor, 0.5/cosθd)` 近似吸收**：头发越黑，透射越暗、越红。不要单独给 TT 一个颜色，否则逆光会出现彩边。
8. **发丝推到头皮外时，TriGrid 只搜 1 格**：查不到就跳过，**不要扩大到全局最近点**。那样耳后、颈后的点可能被错误的远端三角形“推飞”，变成一根根长直线。
9. **体积法线不能用发片法线**：发片法线在片与片之间不连续，会让整片发丝出现条块状明暗。这里用“离开头部中心”的径向法线，只给 Kajiya 漫反射的 wrap 和高光遮蔽用，**真实高光只由切线决定**。
10. **原发片底衬要内收 + 提高 alphaTest**：否则底衬的硬边会比发丝更靠外，在发梢和刘海下沿露出一条“纸片黑边”。
11. **底座半径**（`displayStand.js`）：要用颈部全部下沿顶点的最大半径（+4 mm）来量，只量中段会让后颈从底座侧面穿出。
12. **SwiftShader QA**：3 万根一帧约 1–2 分钟。截图要用 `?qa=1`（渲染 2 帧后停止），并把 `page.screenshot` 的 timeout 调大（qa_render.mjs 已改为 300 s）。`window.__STRAND_STATS__` 会给出引导发数、发丝数、顶点数和耗时；`window.__pick(nx, ny)` 可以射线拾取，用来查“这块怪东西是谁”。

## 5. 局限（如实说明）

- 发型的**轮廓与分缕方式**完全继承发片资产。资产本身的块面感（比如鬓角处发片的硬切边）会以“发丝块”的形式保留下来。要彻底解决，需要真正的 groom 资产（Alembic 曲线），这时本模块的子发、着色、AO 可以直接复用：把引导发换成导入的曲线即可。
- 没有做 **深度阴影 / Deep Opacity Map**，发丝之间的自阴影是 AO 近似的。下一步可以做 4 层 Opacity Shadow Map。
- 没有做 **双重散射**（dual scattering）。浅色头发（金发、亚麻色）的多次散射会偏暗。黑发和深棕发受影响很小。
- 透明度用的是 MSAA 覆盖率，没有 OIT（顺序无关透明）。发梢“柔化”靠变细，而不是靠 alpha。

## 6. 如何迁移到干净分支

```js
import { generateStrands, createStrandMaterial, setStrandParams, morphedHeadSoup, alphaSamplerFromTexture } from './strandHair.js';
const res = generateStrands(cardMesh.geometry, cardMesh.matrixWorld, alphaSamplerFromTexture(cardMat.map), morphedHeadSoup(headSkinMesh), { guides: 2200, childrenPerGuide: 14 });
const mat = createStrandMaterial(res.headCenter);
setStrandParams(mat, { color: [0.032, 0.023, 0.019] });
const strands = new THREE.Mesh(res.geometry, mat); strands.frustumCulled = false; strands.castShadow = false; strands.receiveShadow = true;
head.add(strands);
// 每帧：setStrandParams(mat, { pxScale: 2 * Math.tan(THREE.MathUtils.degToRad(camera.fov) / 2) / renderer.getDrawingBufferSize(v).y });
// 原发片：内收 1.2mm、压暗、alphaTest 0.62、继续 castShadow（见 featureMaterials.js 的 uInset）
```

## 7. v2 升级（Stage 49-C）：从“一坨”到“一根根”

用户反馈 v1 “一看就是假的，一坨，没有细小发丝”。逐项诊断（每项都做过开关对比渲染）：

| 现象 | 根因 | v2 处理 |
|---|---|---|
| 整体像一块光滑的壳 | 原发片作为可见“底衬”铺在发丝下，外层发丝之间看到的是平滑的发片 | 发片 `uScalpFade=1cm`：只保留贴头皮 1cm 内、颜色压到 30% 的遮挡层（硬裁剪），其余发片 **不可见但继续投影** |
| 一片灰白的“塑料光” | R 瓣在竖直发丝上大面积满足 θh≈αR；每根发丝高光完全一致 | 每根 αR 抖动 ±0.06 rad、沿发长 sin 起伏 0.035 rad，强度 0.25–1.75 倍，βR 0.085；高光 × AO²（深层不发亮） |
| 没有细碎发丝 | 子发全部规整地跟着引导发 | 两级成缕（每根引导发 4 个小缕）；12% 散发不成缕；2.2% 飞发（中途弧形离开发束）；每根引导发约 1.6 根短绒毛（6–24mm，卷曲、离开表面） |
| 发梢一刀切 | 子发长度只在 0.8–1 间随机 | `tEnd = 1 − rnd^1.6 × 0.38`（多数接近全长、少数明显更短）+ 发梢 30% 处开始变细变透明 |
| 马尾/盘发侧面全黑 | 旧 AO 用“方位分箱外轮廓半径”，脑后马尾把整个方位的外轮廓推远 | 4mm 体素记录引导发密度，每个点沿离开头心方向走 7 步累积密度 → `0.16 + 0.84·exp(−0.055·Σ)` |
| 锯齿 / 毛线粗 | 发丝固定 0.62px 宽、完全不透明 | 绘制宽 ≥ 0.8px，alpha = 真实宽/绘制宽 × 1.6（发量主体最低 0.82），交给 `alphaToCoverage` + 4×MSAA，再加 ±0.06 抖动 |

### v2 新增的坑
13. **可见底衬 = 灰雾**：试过底衬内收、压暗、按距头皮距离**抖动**剔除，结果都在外层形成半透明的灰色“烟雾”（抖动剔除的屏幕点阵在 MSAA 解析后变成 50% 灰）。最终方案是硬裁剪，只保留 1cm 内的发片，其余只投影。
14. **alpha-to-coverage 只有 4 级**：4×MSAA 下 alpha < 0.125 的发丝直接消失，0.3 左右会出现规则点阵。必须加抖动，而且发量主体要设最低 alpha（0.82）。真实头发几十层叠在一起，**主体本来就是不透明的，只有发梢和碎发才半透明**。
15. **QA 的 URL 参数被滑杆覆盖**：`bindUI()` 里初始化滑杆时会以默认值调用一次回调。用 URL 覆盖着色参数（`hR/hTT/hTRT/hD/hEnv`）必须在 `bindUI()` 之后执行（见 `applyStrandQsOverrides`）。否则会得出“改参数没效果”的错误结论。
16. **诊断用开关渲染**：例如 `?hR=0&hTRT=0`（只看 TT）、`?hR=0&hTRT=0&hTT=0`（只看漫反射+环境光）。v2 就是这样确认了“灰光 = R/TRT，TT 在正面光下可忽略”。
17. **截图文件名每次都要不同**：有的查看器或缓存会把同名图片当成旧图，导致你在看上一轮的结果。
18. **性能**：「标准」4.8 万根、约 2.7M 顶点；引导发追踪约 4–6 s，子发约 0.8 s（headless）。马尾这类短发片的顶点更少（1.7M）。集显请用「流畅」。
